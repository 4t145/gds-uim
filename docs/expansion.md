# 宏展开阶段

`el!` 由过程宏解析完整表达式，再按构造、属性、子元素和后缀的顺序生成 Rust。
非空属性块使用局部绑定，保留方法调用顺序和构建器类型变化；普通子元素直接
连接 `.child(...)`、`.children(...)` 调用。结构类似：

```rust
wrap({
    let element = construct();
    let element = element.flex();
    let element = element.gap(spacing);
    element
}.child(first).children(rest))
```

生成的局部变量使用宏卫生标记，不遮蔽调用方同名变量。
子元素、属性中的 `@if` / `@match` 先绑定父构建器，再按条件选择分支，
各分支返回更新后的构建器。值位置的控制块直接生成 Rust `if` / `match`。

空属性块和空 children 不生成额外作用域。普通子元素和展开列表保持连续的
构建器表达式，避免逐项 `let` 绑定过早结束构造参数、子元素或展开列表中
临时值的生命周期。借用仍需满足 Rust 的作用域规则；需要跨属性块或条件块
复用临时数据时，可以在宏外先绑定数据。

属性、children 和控制块不会额外引入闭包。裸属性闭包、`=>`、`m!` 和 `#?`
按各自语义显式生成闭包，闭包内的 `return`、`break` 和 `?` 遵循 Rust 规则。

一次过程宏调用直接生成嵌套元素树，无需对每个 DSL token 递归调用辅助宏。
Rust 编译器仍检查生成代码的类型和嵌套结构；构建器无需实现 `Clone`。

`tests/expansion.rs` 在默认递归上限下构建并检查 32 层带属性的真实嵌套 DSL，
不通过递归的测试辅助宏生成子树，也不设置更高的 `recursion_limit`。
`tests/el.rs` 继续检查构造、属性、条件、子元素、展开列表、后缀的求值顺序与
所有权，真实 GPUI 测试和示例则覆盖布局、绘制和事件。
