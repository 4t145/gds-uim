# 宏展开阶段

`el!` 的构造、属性、子元素和后缀按顺序执行。非空属性块原本就引入局部绑定；
在这个已有作用域内先完成属性展开，再独立展开子树，结构类似：

```rust
wrap({
    let element = attributes!(construct());
    children!(element)
})
```

这里是结构示意，不是公开 API。属性和后代的宏展开互相独立，属性数量不会再
逐层消耗后代的递归预算。普通、不带泛型参数的完整树节点在遇到结尾逗号时直接
完成解析；其他节点也在阶段结尾的逗号处跳过无用的后缀扫描。
有后缀或泛型参数的节点仍使用完整解析路径，保留相同的求值顺序和类型变化能力。

没有属性或只有空属性时，不能新增上面的作用域。子元素和展开列表之间仍保持
连续的构建器表达式，不能把这些结果改成多个 `let` 或嵌套 `match` 再返回：
构建器可能借用构造参数、子元素、展开列表中的临时值，新作用域会过早结束借用。
也不引入闭包，不改变调用方 `return`、`break` 或 `?` 的作用域。

这些调整只减少无用的解析开销，不消除 Rust 本身的宏递归限制，也不要求构建器
实现 `Clone` 或使用类型擦除。

`tests/expansion.rs` 在默认递归上限下构建并检查 32 层带属性的真实嵌套 DSL，
不通过递归的测试辅助宏生成子树，也不设置更高的 `recursion_limit`。
`tests/el.rs` 继续检查构造、属性、条件、子元素、展开列表、后缀的求值顺序与
所有权，真实 GPUI 测试和示例则覆盖布局、绘制和事件。
